### [ai-memory：为 AI 编码代理提供长期记忆与跨厂商交接的 Rust 工具](https://github.com/akitaonrails/ai-memory) ⭐️ 8.0/10

ai-memory 是一个基于 Rust 的长期记忆工具，专为 AI 编码命令行工具设计，支持在 Claude Code、Codex、Cursor、Gemini CLI 等多个主流代理之间实现任务交接。它通过 MCP 配置和生命周期钩子自动捕获会话上下文，使开发者可以在一个代理中中断任务，然后在另一个代理中继续，无需重新解释架构、失败尝试或未决问题。项目支持 Linux、macOS 和 Windows（通过 WSL2），并提供原生二进制、Docker 镜像和 Arch/AUR 包。当前版本要求 Rust 1.95+，采用 MIT 许可证。

rss · GitHub Trending · All Languages · 8月18日 02:12

**「背景」** 随着 AI 编码代理的普及，开发者经常在多个工具之间切换，但每个代理的会话记忆相互隔离，导致重复解释上下文。ai-memory 旨在解决这一痛点，通过标准化的记忆捕获和交接机制，实现跨代理的连续性。

**「影响」** 对于使用多个 AI 编码工具的开发者，ai-memory 可以显著减少重复沟通成本，提升工作流效率。它支持广泛的代理生态，包括 Claude Code、Codex、Command Code、Devin CLI、OpenCode、Cursor、Gemini CLI、Oh My Pi、Pi、Crush、Kimi Code、Kiro CLI、Grok Build CLI 和 Antigravity CLI 等。部分代理（如 Codex、Antigravity CLI、Kiro CLI）没有自动的会话结束钩子，需要手动运行 \`ai-memory finalize-session\` 来生成最终摘要或交接。此外，某些代理（如 Grok Build CLI、Zero）不支持通过钩子注入交接，需通过 MCP 的 \`memory\_handoff\_accept\` 恢复。
